Introdução

Este documento descreve, em linhas gerais, como os módulos do sistema se conectam e quais decisões guiaram a escolha de cada peça da stack.

O objetivo não é esgotar os detalhes de implementação, mas dar contexto suficiente para que qualquer pessoa do time consiga navegar pelo projeto com segurança.

Arquitetura

O sistema é dividido em serviços independentes que se comunicam por filas de mensagens, reduzindo o acoplamento entre as equipes responsáveis por cada parte.

Cada serviço expõe uma API própria e publica eventos de domínio sempre que um estado relevante muda, permitindo que outros serviços reajam sem consultas diretas.

Camada de Dados

Os dados transacionais ficam em um banco relacional, enquanto os dados de leitura intensa são replicados para um armazenamento otimizado para consultas analíticas.

Migrações de esquema são versionadas e aplicadas automaticamente antes de cada implantação, evitando divergência entre ambientes.

Segurança

Toda comunicação entre serviços é autenticada com tokens de curta duração, renovados automaticamente pelo próprio cliente antes de expirarem.

Auditorias de acesso são registradas em um log imutável, consultável pela equipe de segurança sem intervenção da equipe de desenvolvimento.

Conclusão

A combinação de serviços desacoplados, dados replicados por finalidade e segurança por padrão permite que o sistema cresça sem acumular complexidade acidental.

Novas seções deste documento devem seguir a mesma estrutura: contexto, decisão e consequência.
